# JD 적합성 평가 (JD Fit Evaluator)

unrhyme Training(CareerForge)의 Job Matching POC용 스킬이다. 수요자가 가진 경력·포트폴리오 자료를 채용공고(JD)와 대조하여, **어떤 요구사항에 어떤 근거가 있고 어디에 갭이 있는지**를 설명 가능한 형태로 정리한다.

## 이 스킬이 하는 일 / 하지 않는 일

- 한다: JD 요구사항을 구조화하고, 경력 자료에서 확인되는 근거를 요구사항별로 연결하며, 갭과 이를 입증할 수 있는 작은 프로젝트 방향을 제시한다.
- 하지 않는다: 점수, 퍼센트(예: "84% 적합"), 등급, 합격 확률을 내지 않는다. 이 평가는 합격 여부의 예측이나 특정 직무 역량의 공인이 아니다.
- 하지 않는다: 채용공고를 크롤링·수집하지 않는다. JD는 사용자가 텍스트로 직접 제공한 것만 사용한다.

## 입력

필요한 입력이 빠졌으면 **추측해서 채우지 말고 사용자에게 먼저 묻는다.**

1. **JD 텍스트 (필수):** 사용자가 직접 붙여넣은 채용공고 본문. URL만 받았다면 크롤링하지 않고 본문 텍스트를 붙여넣어 달라고 요청한다.
2. **경력 자료 (1개 이상 필수):**
   - 업로드된 파일: PDF, docx (이력서, 경력기술서, 포트폴리오 문서)
   - 공개 포트폴리오 URL: WebFetch로 읽는다.
3. 자료를 읽지 못한 경우(스캔 PDF 판독 불가, 로그인 필요 페이지, 접근 차단 등)는 우회하지 않고 어떤 자료를 읽지 못했는지 사용자에게 알린 뒤, 파일 재제공이나 텍스트 붙여넣기를 요청한다.
4. 자료에 고객 개인정보·회사 기밀이 포함돼 있으면 리포트에 그대로 옮기지 않고 일반화하거나 제외한다.

## 진행 절차

### 1. 입력 확인
JD 텍스트와 경력 자료가 모두 있는지 확인한다. 어느 쪽이든 부족하면 질문하고 멈춘다.

### 2. JD 구조화
JD에 **적혀 있는 내용만** 다음 항목으로 나눈다. JD에 없는 항목은 "JD에 명시 없음"으로 두고 채워 넣지 않는다.
- 직무명 / 주요 업무(책임)
- 필수 요건
- 우대 사항
- 도메인·산업 맥락
- 기타 조건(경력 연차, 근무 형태 등 JD에 명시된 것)

### 3. 경력 자료에서 근거 추출
자료를 읽고 JD 요구사항과 대조할 수 있는 근거를 뽑는다. 모든 근거에는 **출처(파일명·페이지/섹션 또는 URL)** 를 함께 적는다. 자료에 쓰여 있지 않은 경험·역량은 추정하거나 보완하지 않는다.

### 4. 요구사항별 판정
JD의 각 요구사항(필수·우대 모두)에 대해 다음 중 하나로 판정한다.

| 판정 | 기준 |
|---|---|
| 근거 확인 | 자료에 해당 역량·경험을 직접 보여주는 구체적 근거가 있다 |
| 부분 근거 | 인접하거나 일부만 보여주는 근거가 있다. 어디까지 확인되고 무엇이 비는지 명시한다 |
| 근거 없음 (갭) | 자료에서 근거를 찾을 수 없다. 자료에 없다는 뜻이며 역량이 없다는 단정은 아니다 |

- 근거가 없는 스킬은 맞는 것으로 판정하지 않는다.
- 각 판정 옆에 서술을 **Fact / Interpretation / Assumption**으로 구분한다.
  - Fact: 자료에 직접 쓰여 있는 내용
  - Interpretation: 사실을 바탕으로 한 해석 (해석임을 밝힌다)
  - Assumption: 확인되지 않은 가정 (가정임을 밝히고, 가능하면 사용자에게 확인할 질문으로 돌린다)

### 5. 평가 차원별 서술
다음 다섯 차원으로 정리한다. 숫자 점수·가중치는 쓰지 않고, 근거를 인용한 서술로 설명한다.
1. 직무 일치: 주요 업무와 경력 경험의 겹침
2. 필수 역량: 필수 요건에 대한 근거 확인 정도
3. 프로젝트 근거: 역량을 보여주는 공개·검증 가능한 결과물이 있는가
4. 우대 역량: 우대 사항에 대한 근거
5. 도메인: 산업·업무 맥락 이해를 보여주는 경험

### 6. 갭과 입증 방안
'근거 없음'과 '부분 근거'로 판정된 요구사항마다 **그 역량을 입증하기 위해 만들 수 있는 작은 프로젝트나 산출물**을 제안한다. 제안은 초급자가 짧은 시간 안에 작동하는 최소 결과물을 만들 수 있는 규모로 하며, 입증 방법(무엇을 만들면 이 요구사항의 근거가 되는지)을 함께 적는다.

### 7. 종합 서술
점수 없이, 강점 근거와 핵심 갭을 중심으로 3~5문장으로 종합한다. 합격 가능성이나 지원 여부에 대한 단정적 권유는 하지 않는다.

### 8. Markdown 파일로 저장
아래 템플릿으로 리포트를 Markdown 파일로 작성하고 사용자에게 전달한다. **저장 위치와 파일명은 사용자가 지정한 대로 따르며, 지정이 없으면 저장하기 전에 묻는다.**

(직무명, 주요 업무, 필수 요건, 우대 사항, 도메인 맥락 — JD에 있는 내용만)

## 3. 요구사항별 근거 매핑
| 요구사항 | 필수/우대 | 판정 | 근거 (출처 위치) | 구분 (Fact/Interpretation/Assumption) |

## 가드레일

- 근거 없는 경험·성과·수치를 만들어 넣지 않는다. 사용자의 경력을 과장하거나 보완해서 쓰지 않는다.
- 자료에 없는 내용은 "근거 없음"으로 두고, 필요하면 확인 질문으로 돌린다.
- AI의 판정은 확정이 아닌 근거 기반 의견이다. 사용자가 근거를 직접 확인할 수 있도록 출처 위치를 반드시 남긴다.
- 공개 URL이 접근 제한·이용약관 문제로 읽히지 않으면 우회하지 않는다.
- 개인정보·회사 기밀·API 키는 리포트에 옮기지 않는다.
